# AI Coding Framework 简要框架

## 一、核心问题

1. **质量控制**：AI 生成速度远超验证速度，如何自动化保障质量？
2. **信任边界**：AI 会偷懒、欺骗、走偏，人在哪里介入？
3. **组织落地**：从个人到团队，如何标准化、可复制、可衡量？

## 二、问题逻辑关系

**质量控制** 是核心 → AI 生成快但质量难保证，引发 **信任边界** 问题（人看不过来，如何相信 AI 输出？）→ 必须通过 **自动化质量闭环** 解决（测试、文档、流程约束）→ 个人能跑通后，才能谈 **组织落地**（标准化、ROI、协作）

核心矛盾：AI 提速的同时，质量保障必须从"人工审核"转向"自动化验证 + 人类抽查"

## 三、我们的主张

**软件工程本质未变，但瓶颈和成本结构已转移**：

软件工程的核心挑战始终是：在约束条件下交付可靠系统。AI Coding 没有改变这个挑战，但改变了：
- **瓶颈转移**：从"写代码慢"转向"验证质量慢"
- **成本结构改变**：从"人力写代码"转向"Token 消耗 + 质量基础设施"
- **手段必须变化**：传统 Code Review 无法匹配 AI 生成速度，必须前置质量保障

**AI Coding 不是工具升级，是研发体系重构**：
- 质量保障从依赖人工审核转向自动化闭环验证
- 组织能力从"招聘熟练工"转向"设计约束系统"

**编码成本坍塌：好实践不再需要妥协**：
- 根本驱动力：编码成本数量级下降 → 过去"理论正确但经济不可行"的实践成为默认
- 测试、文档、重构、架构约束——都是一直该做但做不起的事，现在做得起了
- 刚性架构：Agent 在严格边界中最有效（OpenAI 验证），编码便宜后好架构不再是奢侈品
- 架构师 + AI 参谋：设计基于代码/文档的真实状态，而非过时的心智模型
- 这是后续所有解决方案的经济基础

**三大支柱**（质量控制的实现路径）：
1. **文档驱动**（需求、验收标准、API 契约 → 约束 AI 输入输出）
2. **测试先行**（端到端、回归、文档测试 → 自动验证 AI 输出）
3. **角色对抗**（subagent、政委角色、质量检查 → AI 自我纠错）

**关键机制：Skill 体系**
- Skill = 可复用的工作流程（封装最佳实践、质量检查、流程约束）
- 从个人经验到组织资产：通过 skill 沉淀和共享标准化工作方式
- 组织能力可积累、可迭代、可度量

管理层决策重点：投资 skill 体系建设和质量基础设施，而非增加代码审核人力。
